# A 股 ETF RS 轮动组合回撤期保护研究 2026-06-05

## 研究目的

本轮只研究“组合进入回撤/弱势阶段后的保护”，不研究常态 SuperTrend 压仓。主策略保持不变：

```text
RS Rotation top5 + 510300.SS monthly_macd
```

保护层只改变总仓位倍率，不替代月 MACD，不使用标的级 ST 否决买入。

## 口径

- 样本：`backend/universes/a_share_etf_core.json`
- 本地可用缓存：21 个 A 股 ETF
- 市场代理：`510300.SS`
- 区间：本地数据实际从 `2021-05-06` 到 `2026-06-04`
- 选标的：RS top5
- 再平衡：20 个交易日
- RS lookback：60 日
- 成本：单边手续费 5 bps，单边滑点 5 bps
- 触发/恢复信号：未加保护的主策略影子净值，避免保护组合因低仓位恢复慢而长期自锁

输出文件：

```text
backend/backtest_results/rs_drawdown_protection_2026-06-05.json
```

运行命令：

```bash
cd backend
PYTHONPATH=. uv run python ../scripts/research_rs_drawdown_protection.py \
  --output backtest_results/rs_drawdown_protection_2026-06-05.json
```

## 关键观察

### 1. A 方案仍然太像常态压仓

只用组合回撤阈值触发，即使用主策略影子净值做恢复信号，保护天数仍有 `39.69%` 到 `69.72%`。它能降低回撤，但收益牺牲太大，不符合“只在回撤期保护”的目标。

### 2. B 方案比 A 更接近可用，但收益/回撤仍未超过主策略

B2 的严格确认明显减少保护天数：

- `DD 12 + 日 ST 连续弱势 + 周线非多 + 85%`：保护天数 `21.75%`，收益保留 `88.98%`
- 但最大回撤只从 `23.75%` 降到 `22.82%`，下降 `3.92%`

更防守的 B2：

- `DD 8 + 日 ST 连续弱势 + 周线非多 + 65%`：回撤下降 `14.21%`
- 但收益保留只有 `78.49%`，收益/回撤比 `1.82`，仍低于主策略 `1.99`

### 3. 周线确认减少误触发，但会牺牲保护力度

周线 ST 非多确认能把保护天数从 B1 的 `35.47%` 降到 B2 的 `21.75%`，更符合“不常态压仓”。但它也错过一部分回撤保护窗口，回撤下降有限。

### 4. 2024 是主要拖累年份

主策略 2024 收益 `36.44%`，B2 轻保护为 `31.62%`。保护层在 2024 有 `73.97%` 的保护天数，占用了强修复阶段，解释了收益/回撤比没有超过主策略。

## 结论

1. **不建议把组合回撤保护作为默认策略层产品化。**
2. **A 方案失败：保护天数过高，本质上仍接近常态压仓。**
3. **B 方案方向更合理，但当前参数没有跑赢主策略收益/回撤比。**
4. **当前最接近可用的是 B2 轻保护：收益保留接近 89%，保护天数 21.75%，但回撤下降只有 3.92%，价值不足。**
5. **如果要做产品功能，只适合做“手动保守模式/压力模式”，不适合默认开启。**

一句话：

```text
组合回撤期保护比固定 ST 压仓更合理，但在当前 A 股 ETF RS + 月 MACD 主策略上，保护层还没有证明能提升收益/回撤比。
```

## 下一步

暂不改变默认策略。若继续研究，优先测试更短的保护半衰期，例如触发后最多保护 20/40/60 个交易日，到期必须恢复，再由新信号重新触发。这样可以直接约束“保护期拖过强修复年份”的问题。
