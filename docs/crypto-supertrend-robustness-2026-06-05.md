# Crypto SuperTrend 精选模式稳健性评估 2026-06-05

本报告回答一个具体问题：`周线 + 日线 ST + BB p20` 这个 Crypto 精选模式，是否只是近五年 BTC/ETH 的偶然结果。

## 结论

需要看更长周期，而且看完后结论更清楚：

- 这个精选模式不是最高收益策略。
- 它的核心价值是显著降低回撤、降低交易频率、避开部分熊市年份。
- 它适合作为 Crypto 的“低频精选/风控视图”，不适合作为默认收益最大化策略。
- 默认日线 ST 仍然更适合做主雷达；精选模式适合作为第二层筛选。

## 方法

临时使用 `yfinance` 下载 BTC/ETH 长历史数据，不写入 `backend/data` 主缓存。

数据范围：

- `BTC-USD`：2016-01-01 至 2026-06-05。
- `ETH-USD`：yfinance 可用历史内自动截取。

执行口径沿用研究脚本：

- 收盘确认信号。
- 下一根日线开盘执行。
- 单边手续费 5 bps，单边滑点 5 bps。

临时命令：

```bash
uv run --directory backend python <临时研究脚本> > /tmp/crypto_10y_robustness_local.json
```

比较策略：

- 买入持有。
- 日线 ST。
- 周线 ST。
- 周线 + 日线 ST。
- 日线 ST + BB p20。
- 周线 + 日线 ST + BB p20。

## 更好的评估方案

近十年年度表现是必要的，但还不够。更好的评估应该分四层：

1. 年度拆分  
   看策略是否只靠一两年赚钱，是否能避开熊市。

2. 滚动窗口  
   使用 3/4/5 年滚动窗口，观察不同起点是否仍然有低回撤优势。

3. 参数敏感性  
   不只看 `BB p20`，还要比较 `p15/p20/p25/p30`；不只看 `ST(7,3)`，也要比较 `ST(5,3)`、`ST(10,3)`。

4. 样本扩展  
   BTC/ETH 仍然太少。后续应加入 SOL、BNB、ADA 等，但必须注意 yfinance 加密货币历史长度、流动性和生存者偏差。

5. 样本外/走步验证  
   例如用 2016-2020 选参数，2021-2026 验证；或每 3 年滚动选参数，下一年验证。

6. 交易数约束  
   如果一个策略十年只交易 1-3 次，不能因为收益回撤比好就直接产品化。需要设最低交易数或把它标记为“极低频提醒”。

## 产品化判断

这个精选模式可以继续作为 Crypto 研究视图候选，但不应替代默认 ST。

推荐定位：

- 默认雷达：日线 ST(7,3)。
- 趋势大方向：周线 ST。
- 低频精选：周线 + 日线 ST + BB p20。

推荐 UI 文案方向：

```text
Crypto 精选：只显示周线多头、日线翻多且波动压缩后的机会。信号少，偏防守，不追求吃完整段趋势。
```

暂不建议：

- 把 `周线 + BB p20` 当作默认买卖策略。
- 用它评价所有 Crypto。
- 只凭 BTC/ETH 近五年收益就上线交易逻辑。

下一步：

- 扩展 Crypto 样本。
- 做 `BB p15/p20/p25/p30` 敏感性。
- 做走步验证。
- 如果仍稳定，再接入前端研究模式。
