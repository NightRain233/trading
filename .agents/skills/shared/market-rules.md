# 看盘口径（scan / analyze / fupan 共用）

所有分析先读本文件。它规定看什么、按什么顺序看、哪些结论不能下。

## 1. 主线和边界

- **唯一主策略**是 `btc_supertrend_satellite`：沪深300ETF / 纳指100ETF / 黄金ETF 按 20 日逆波动配比（每 10 个交易日检查一次），加 7.5% 的 BTC 卫星，BTC 由日线 SuperTrend(10, 3, SMA ATR) 在检查日决定持有或换成现金。
- 主策略的持仓**不因任何技术信号增减**。温斯坦阶段、SuperTrend 扫描、RSI 等只用于学习和观察；不得据此建议卖出或加仓主策略里的品种。
- 冻结研究结论（xquant `docs/notes/weinstein-summary-2026-10-18.md`）：
  - A 股：所有择时（温斯坦、风格轮动、指标组合）都跑输一直持有。A 股只看状态，不给择时操作建议。
  - 美股指数和 ETF：温斯坦规则能明显降低回撤，是"学习账户"的纸面练习对象。
  - BTC：日线 ST 最好，已在主策略里；周线只作参考。
  - 黄金：温斯坦规则没有单独测过，只看状态，不当信号。
- 用户是非技术背景的普通投资者：结论先行，中文、通俗，少术语；涉及数字时说清楚它意味着什么。

## 2. 数据来源

```bash
# 周末复盘 / 市场扫描（约 30KB）
uv run python scripts/trading_analysis_helper.py --query weekly --timeout 120
# 单标的（约 4KB）
uv run python scripts/trading_analysis_helper.py --query brief --symbol <SYMBOL> --timeout 120
```

- 默认读本地 `http://127.0.0.1:8000/api`。用户要求生产数据时，用环境变量 `TRADING_API_BASE` 或 `--api-base` 指向服务器；**不要把服务器地址写进仓库文件**。
- 一次分析只用一个来源，并说明来源和数据日期（`weekLabel`、`latestDataDate`、主策略 `dates.marketDataDate`）。
- 连接失败就说"数据不可用"，不能当成"没有信号"。
- 需要 SuperTrend 全部字段时才用 `--query overview`（约 1MB），先想清楚是否真的需要。

## 3. 温斯坦周线口径

| 项目 | 口径 |
|---|---|
| 均线 | 30 周简单均线；斜率 = 4 周变化，绝对值 < 0.4% 算走平 |
| 阶段 | 二 上涨：价在上升的 30 周线上方；四 下跌：价在下降的 30 周线下方；三 做顶：走平或价跌破仍在上升的 30 周线；一 筑底：走平或价站上仍在下降的 30 周线 |
| 缓冲 | 价格离 30 周线 2% 以内不换阶段，避免来回横跳 |
| 相对强度 | 26 周涨幅减去基准 26 周涨幅。.SS/.SZ 比沪深300（000300.SS），美股比 SPY，.HK 比 2800.HK；加密、商品和跟踪海外/商品的 A 股 ETF（黄金ETF、纳指100ETF 等）没有基准，港股类 ETF 比 2800.HK。`rsBenchmark` 为空时不谈强弱 |
| 布林带 | 20 周、2 倍标准差；`squeeze` 收窄中，`squeeze_breakout` 收窄后突破上轨，`above_upper` 在上轨之上 |
| 量比 | 上周（已收盘）成交量 / 之前 10 周平均。本周没走完的量不比较 |
| 规则状态 | `entry` 新进第二阶段（前 4 周且相对强度为正）→ 可买；`hold` 持有；`exit` 跌破 30 周线 2% 以上 → 卖；`caution` 涨势松动；`out` 不持有；`wait` 观望 |

- **阶段、规则、相对强度、量比一律用上周已收盘的周线**（helper 已经这样给出，`closedWeek` 是那一周）。本周没走完时，`now.provisionalStage` 只能写成"暂定"，周五收盘后才算数。
- "已确认的换阶段"只来自 `stageChanges`；"暂定的换阶段"只来自 `provisionalStageChanges`，两者分开写，不要自己比较两周数据。
- 位置用 helper 算好的数，**不要自己心算价位或距离**：
  - `levels`：下一个周收盘在 `price` 之上（`side=above`）或之下（`below`）就换成 `becomesStage`；`price` 已经算进这次收盘对 30 周线的拉动，是精确触发价，不要再说"约"或自己调整。
    - 距离默认用 `changePct`（离**上周收盘价**，不随盘中漂动），远近看 `typicalMoves`（几次正常的一周涨跌）：1 以内是"一个普通的周就能碰到"，3 以上算宽裕；`far=true` 只写"很远"，不报次数。
    - `changePctNow` 是离最新价的距离，只在说"这周到现在"时用，并注明截至 `now.asOf`、是否盘中（`now.sessionComplete=false`）。
  - `bandPositionPct`（行上）：上周收盘时在 20 周布林带里的位置（0 下轨、100 上轨；负数是已跌出下轨，超过 100 是已涨出上轨），和阶段同一口径，表格里用它；`now.bandPositionPct` 是最新价的位置。
  - 量能只用 `volumeLabel`（放量 / 正常 / 缩量，门槛 1.5 / 0.7），不要自己把 1.1、1.2 说成"放量"。
  - 下降的 30 周线被站上只会变成第一阶段（筑底），不是上涨；`levels` 已经区分，照它写。
- 行上有 `warning`（缺少已收盘周数据）时，这个品种的阶段只能写"暂定"，并说明原因。
- `conflict=true`：上周确认换阶段、本周又暂定换回去，要点明"周五若成立，上周那次是假信号"。
- 每个价位都要写清**属于哪套规则**：温斯坦线是学习/观察口径；主策略的 BTC 开关是 `btcSwitch`（检查日看日线 ST，下一交易日收盘执行，两次检查之间跌穿不会卖，**不是止损**）。两者不放在同一行里比。

## 3.1 指标打架时听谁的

结构（阶段 + 关键价位）> 相对强度 > 量价 > 动能（MACD、RSI 等）。动能只能做"提前预警"，不能单独推翻结构的结论；写报告时按这个顺序得出一句话，不要把五个指标并列让读者自己权衡。

## 4. 大盘环境

- 大盘阶段**以温斯坦周线为准**：沪深300、SPY、QQQ、BTC、黄金ETF（`benchmarks`）。
- SuperTrend 的 `marketModes` 用的是月线方向，反应更慢。它和周线阶段冲突时，照实说明"两套口径不一致"，以周线为大盘结论，不要拿 `marketModes` 推出 A 股"可以找机会"。

## 5. SuperTrend 学习层

- 扫描分组、`decision.permission` 等含义见 [supertrend-decision-contract.md](supertrend-decision-contract.md)。只在用户问到具体 SuperTrend 信号时展开。
- 默认压成一行："学习观察：X 个等待确认，Y 个正式买点"。任何 SuperTrend 结论都不得覆盖主策略或温斯坦规则状态。
- 主策略 BTC 开关用的是自己的 ST(10, 3)，不要和扫描里的 BTC 状态（参数不同）混为一谈。

## 6. 不能下的结论

- 不能把"观察到的阶段"说成"应该卖出主策略持仓"。
- 不能给 A 股品种写"买入/卖出"建议；只能写状态和"如果要学，看什么"。
- 不能说"已成交""已调仓"，除非账本（`operations.orders`、`ledger`）显示如此。
- 不编造仓位数量、成本或止损；复盘文件里没有就说没有。
- 不用"已经跌（涨）了 N 周"推断要反弹（见顶）。持续周数只说明这是新趋势还是老趋势，不预测转折。
- 在有历史基础概率数据之前，不用"大概率""通常""一般会""正常回调""健康调整"这类预测或定性词；只描述位置、方向和量能标签。
- 阶段只描述现状，不预测走势：A 股按阶段择时没有跑赢一直持有，黄金没测过。说主策略仓位处在下跌阶段时，必须同时说明这一点，不能推出"会拖累""该减"。
- 不把模型自己算的数字写成事实：价位、距离、波动折算都以 helper 字段为准；helper 没给的就不给。
- 主策略账户 `accountStatus` 不是"已建仓"时，报告第一句先说这件事。
